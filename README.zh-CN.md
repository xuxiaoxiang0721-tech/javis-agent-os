# Javis — 让 AI 团队记得住，也做得到

**本地优先的 AI 多角色工作台：持久记忆、任务协作、过程可追溯。**

[English](README.md) · [架构](docs/architecture.md) · [配置说明](docs/setup.md) · [验证记录](docs/validation.md) · [MIT 许可](LICENSE)

Javis 以 Grok 为对话入口、Codex 为本地执行器，把角色分工、任务状态、原始记录、可审核记忆和浏览器工作台连接起来，让持续进行的 AI 工作有据可查。

> 当前是从个人部署整理出的开发预览版。离线演示可以独立运行；真实机器人、模型服务和定时任务需要自行配置。仓库名中的 Agent OS 指工作台层，并非操作系统。

## 它能做什么？

- **让多个角色各司其职**：独立角色工作区、任务路由、原子投递队列和重复提交保护。
- **让记忆有来源**：结构化事实、原文引用、确认记录、修订，以及可选的 Graphiti / Neo4j 图谱。
- **让执行有证据**：记录输入、执行尝试、正式回执与产物引用，区分“已接收”和“已完成”。
- **让人能查看和确认**：本地任务、记忆、用量界面，以及基于 passkey 的所有者验证。
- **让数据边界明确**：本地凭据存储、敏感内容脱敏、原文加密保存和执行器访问范围控制。

示例注册表包含 12 个角色。仓库中的机器人 ID 已替换为合成占位值。

## 不用 API Key，先体验任务流程

在 Linux 或 WSL 中准备 Python 3.10+：

```bash
git clone https://github.com/xuxiaoxiang0721-tech/javis-agent-os.git
cd javis-agent-os
python3 examples/offline_demo.py
```

演示会在临时目录中创建一个合成任务，重复提交并验证去重，读取排队状态和原始记录，然后清理演示数据。它不会启动执行器，也不会调用模型。

浏览器工作台和真实集成的配置见 [Setup](docs/setup.md)。Windows 调度脚本仍是需要适配路径的参考模板。

## 公开范围

包含任务运行时、记忆模块、工作台、测试和公开数据结构。私人对话、记忆库内容、账号密钥、运行状态、备份与个人配置均不包含在仓库中。

本次验证针对公开副本的离线演示和选定回归测试；不代表全新机器完整部署、云端往返或无人值守审批已经验收。
